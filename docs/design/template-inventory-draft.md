# 模板清单草稿（全量）

> 状态：草稿，供设计评审。依据：逐块精读 lua/ 下全部 45 个文件（39 挑战 + CODE.代码模板 + 5 个 utils），共 359 个代码块。
> 本文档只盘点与建议，不改动设计定稿；与设计定稿 §6 的关系见 1.0。

## 0. 口径与方法

- **块编号**：`块N` = 文件内顺序号（0 = 前置代码块，与前端自动编号一致）；`注释号N` = 作者在说明注释里手写的 `--N.` 编号。两者在大多数文件一致，**不一致处见 §4 异常**（23 跳号、34 重号、15 前导空格）。注释中"依赖代码N"指的是注释号。
- **逐字节验证**：对每组疑似共享代码计算代码体 md5；对"仅参数不同"的家族，先把参数字面量（ITEMS 表 / id 列表 / 默认值）归一化再比对骨架。下文标注为：
  - ✅逐字节一致：所有使用点 md5 相同，零差异；
  - ☑️骨架一致：仅声明的参数值不同，归一化后逐字节相同；
  - ⚠️变体：形似但实现有实质差异，逐条见 §4。
- **`-1.灵感.lua` 现状结构**（类模板未来的家）：文件头仅 `--灵感` 一行；随后 17 个代码块（注释号 1–17），每块 = 说明注释（多数附"灵感来源:bilibili@…"署名行）+ 一条 `l ` 压缩代码行；无前置/后置块、无 `--===--` 分隔线（符合 utils 自由格式）。其中 5 个块的注释已声明可自定义参数（块1 Burst、块2 PoisonNum、块3 Threshold、块6 Hail/HailNum、块7 Dist），参数均为代码行首的全局变量赋值。块4 注明"需要忏悔龙"。

## 4. 异常与边界

1. **23.子弹时间 注释号跳号**：块序列的注释号为 0,1,3,4,5,6,7,8,9——**没有注释号 2**。"依赖代码3"在新体系自动连续编号（0..N）后，文本中的"代码3"将由"注释号3"变成"第 3 块"（= 注释号4），**所有手写"依赖代码N"文本在迁移后都会错位**，需随迁移改写为按名称引用或更新文本。
2. **34.归途无期 注释号重复**：块12（移除卡牌 73/92）与块13（移除饰品 138/154）的注释号**都是 12**（前端对重复编号回退为行号 id）。
3. **15.勇往直前 注释号前导空格**：块1–4 的注释写作 `-- 1.`（数字前有空格），不匹配前端 `--(\d+)\.` 编号正则，这些块在前端无编号锚点——"依赖代码1/代码2"实际指向它们，纯靠文本语义维系。
4. **合辑块25 注释号格式**：`--25 .实时监测…`（数字后空格再点），同样不匹配编号正则。
5. **25 块5 隐藏依赖**（§3 #13）：调用 D4/D4_1 但注释只字未提，迁移时若重排块顺序会静默出错——构建期依赖校验救不了未声明的依赖，需人工补声明。
6. **依赖实现方式不统一**：全局变量标记（`_Y`）、全局函数调用（`SetTimeScale/_Data/GetDoorId`）、**覆盖式重定义**（28块2 重写 `OnHit`——依赖方向是"后来者覆盖先来者"，块1 必须先执行占位定义，顺序颠倒则 28块2 的定义先存在、随后被块1 的空 `function OnHit(p)end` 覆盖而失效）。依赖校验必须保证 28块1 在 28块2 之前。
7. **15块5（免疫 4 诅咒）vs `curse-immune` 模板**：实现实质不同（371 vs 122 字符；多用 MC_USE_PILL 处理失忆药/???药两个 PillEffect + MC_POST_CURSE_EVAL 位掩码），形似神异，应保留自定义或单列变体。
8. **15块3（开图）vs 12块1**：15块3 多了 `VisitedCount>0 时保留红色标签` 的条件分支（配合"每房仅进一次"玩法），形似神异。
9. **15块1（数据保存变体）**：与 24块1/DEBUG3块6（`persistent-data`）实现不同（rewind 语义相反：15 版 rewind 触发重置，24 版 rewind 可回溯），ADR 已定保留自定义，此处仅复核确认差异属实（1000 vs 1106 字符，回调结构与 `_rew()` 定义均不同）。
10. **14块1（移除道具特判）**：`remove-collectibles` 骨架 + `and c~=580`（不阻止红钥匙效果触发）。可作模板的"例外 id"第二参数，或保留自定义。
11. **28块1 vs 合辑块40（`on-hit-detect`）**：28块1 多一个 MC_POST_NEW_ROOM 的房间切换清理回调（合辑块40 没有）。以哪份为模板主体待定（建议以 28块1 为完整版，合辑块40 迁移时补齐——**但这违反字节级等价验收门，需显式决策**）。
12. **16块3（强制堕化店主）**：`force-character` 骨架 + 副手金剃刀片 + 移速=金钱×0.003 的扩展，超出模板单参数能力，保留自定义或拆两块。
13. **35块5（拉撒路→死亡拉撒路）**：条件触发的角色转换，与 `force-character` 形似（都用 ChangePlayerType）但语义是"转换"非"强制"，保留自定义。
14. **御灵术块2 参数非 token 化**：15 个 `{参数}` 中约 1/3 是效果类型/描述性语义（灼烧/中毒/冰冻/圣光/玩家泪弹），无法落为 P1..Pn 占位符的单值替换（设计 §3.2 要求 token 边界匹配），参数化方案**待人工**。
15. **29块1 注释风格不一致**：`SHUFFLE=8` 是全局参数但注释未写"默认 8"，只写 `(1/SHUFFLE)*100%`，与其他块的"xx(默认N)"格式不统一。
16. **`per-floor-give-collectibles` 仅 1 处使用**（合辑块30）：不满足"≥2 处"共享标准，但与 `per-floor-spawn-collectibles` 共享 Items 参数格式，建议合并为一个双模式模板或缓收。
17. **`state-machine` 参数化价值低**：合辑块42 内嵌 5 态实例，"参数"是整个 map 函数表，超出标量/列表参数模型，建议保持无参模板。
18. **CODE.代码模板.lua 文件头是骨架模板**：5 行（挑战名称/禁用角色/限定角色/禁止难度/限定难度），新体系下是"文件头"的填写样例，迁移时 39 个挑战的文件头原样直通即可，无需处理。
19. **跨文件"依赖函数原型"的建模缺口**：25 的 D4 块注释声明依赖"函数原型 RandomItems"——若 RandomItems 以模板身份栖息 utils、25 的 D4 改为模板引用，则 25 文件内不再有 RandomItems 块可供"依赖"声明指向，设计 §3.4 的依赖（同文件名称）无法表达，需要在迁移方案中显式处理（如：模板引用块按引用顺序自动保证先后，或允许依赖值为模板id）。
