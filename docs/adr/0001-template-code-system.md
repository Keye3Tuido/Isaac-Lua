# 模板代码系统：YAML 头 + 构建期替换 + 全量迁移新格式

以撒代码挑战的 45 个 Lua 文件从"注释 + 压缩单行"的自由格式，迁移到"YAML 头驱动的模板代码系统"：代码块通过 `--[[ ]]` 包裹的 YAML 头声明元数据，可引用 `lua/utils/` 中的模板并传参，构建期完成参数替换与校验后输出最终代码。

关键决策与理由：

- **模板仅栖息于 `lua/utils/`**，challenges 内声明模板无效（构建警告）。单一事实源，工具与作品分目录。
- **参数用占位符 `P1..Pn`（全局名 token）而非锚点/魔法数字**，构建期做 token 边界替换 + LuaMin 语法校验。代码体与说明文本（`{P1}` 插值槽）共用同一套参数；列表参数进代码用 `,`、进文本用 `、`，天然支持不定长。
- **替换发生在构建期（GenerateHtml.py），不在前端运行时。** 前端、复制、下载、kb.json 拿到的永远是替换后的最终内容，YAML 头对读者不可见。
- **迁移只认新格式，不做双格式兼容层**（已拒绝：长期共存会让两种心智模型互相污染）。验收门替代兼容层：迁移后每个文件的最终代码（全部代码行拼接）必须与迁移前逐字节一致。
- **模板存压缩单行形态**；utils 中可读源码（DEBUG1 v2、DEBUG3 头部）用多行注释注释化保留作参考（已拒绝"存可读源码 + 构建期内嵌 LuaMin 压缩"：占位符会被压缩器全局折叠破坏，且构建链变重）。
- **依赖 = 文件内顺序与存在性约束**（构建期校验被依赖块存在且在前），不做代码内联（已拒绝：违背控制台逐行执行语义）。
- **参数性质（全局/局部）仅作文档标注**，不做全局提升注入（已拒绝：全局变量的意义是让玩家游玩时手改，构建期无需处理）。
- **15.勇往直前的数据保存变体保留为自定义代码**（已拒绝统一回模板原版：其退出处理逻辑有语义修改，统一会改变玩法）。
